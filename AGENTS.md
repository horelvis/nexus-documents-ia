# Repository Guidelines

## Project Structure & Module Organization
Core FastAPI services live in `backend/app` (domain modules, routers, background jobs) with companion microservices inside `backend/microservices` and Docker tooling in `backend/docker`. Next.js UI code resides in `frontend/app`, while reusable widgets are under `frontend/components` and shared hooks/utilities in `frontend/lib`. Infrastructure manifests and rollout scripts are grouped inside `deployment/` and `nginx/`. Automation, migrations, and helper utilities sit in `scripts/`, and integration artifacts generated by agents belong in `src/contexts` to keep the top-level clean.

## Build, Test, and Development Commands
```bash
cd backend/docker && ./start-dev.sh    # boot FastAPI, Temporal, and dependencies via Docker
cd frontend && npm run dev             # Next.js dev server with Turbo
cd frontend && npm run build           # production-ready bundle
cd backend && python scripts/alembic_safe_migrate.py   # safe DB migrations
./run-tests.sh --full                  # containerized suites (unit+integration)
```
Prefer `./run-tests.sh --quick` for smoke checks and `--coverage` when updating service contracts—the report lands in `backend/coverage_report/`.

## Coding Style & Naming Conventions
Python code follows PEP 8 with type hints; favor dependency-injected services and FastAPI routers per module (e.g., `app/api/v1/documents.py`). Keep async endpoints suffixed with `_async` only when a sync version also exists. JavaScript/TypeScript files use ESLint via `npm run lint`, 2-space indentation, and PascalCase for exported React components while hooks/utilities stay camelCase. Align environment filenames with the existing pattern: `.env`, `.env.test`, and `.env.prod`.

## Testing Guidelines
Backend tests run through Pytest (configured in `backend/pyproject.toml`) and should mirror feature folders under `backend/tests`. Name files `test_<feature>.py` and tag long-running workflows with `@pytest.mark.integration`. Frontend end-to-end flows use Cypress (`npm run test:e2e`) and should live in `frontend/cypress/e2e/` mirroring user journeys. Keep coverage above 80% on new modules and provide fixtures for external APIs instead of hitting live services.

## Commit & Pull Request Guidelines
Commits follow the conventional short prefix observed in history (`feat(scope): ...`, `fix: ...`, `chore: ...`). Reference the affected domain in the scope, e.g., `feat(template-editor): ...`. Every pull request must include: summary of changes, deployment/test notes (commands executed), linked issue or document, and screenshots/GIFs for UI-impacting work. Flag migrations or infra toggles explicitly so reviewers can coordinate rollouts.

## Security & Configuration Tips
Copy baseline env files (`cp .env.example .env`) and inject real secrets via your secret manager or `.env.local` ignored by Git. Do not commit files from `backend/credentials/` or any `*.key`. When working with GCP scripts in `deployment/`, confirm service accounts have least privilege and rotate keys after testing.
